Assimilate · frontend proposal

Agent detail, unstacked

The Overview tab of an agent is where you land when a backup fails at 3am. Today it opens on a nine-row definition list, eight undifferentiated buttons and six configuration cards — and not one backup result. This is a redesign that puts the operational answer first and moves every setting behind one tab.

The problem

Everything is a card, so nothing is important

AgentDetailView.vue renders the Overview tab as one vertical run of .info-card blocks, each with the same border, the same .info-title and the same bottom-right Edit button. Two of them (Edit Identity, Deploy SSH Key) are not cards at all but inline expanders that shove everything below them down the page. The drawing below is to scale.

Where everything went

Nothing is removed, eleven things move

Every control on the page today survives. The change is which of them you see without asking.

TodayProposedWhy
Agent Information list Header meta strip + Settings › Identity Version, revision and build time are looked up once a quarter; they do not deserve nine rows above the fold.
Status badge Header, next to the hostname Visible on every tab, not only Overview.
Activity Log button Header, kept as a button Navigation, used often enough to stay visible.
Edit / Regenerate Token / Restart / Deploy SSH Key Header overflow menu Rare or destructive. Four ghost buttons that looked identical to Activity Log now sit behind one affordance.
Deploy / Upgrade button Header primary button, only when an upgrade exists Conditional and actionable, so it earns the one accented slot.
Merge into… / Adopt (imported hosts) Header primary pair on imported hosts An imported host has exactly one job: get adopted or merged.

Deploy SSH Key inline panel Modal from the overflow menu Same reason.
Four Default… cards Settings › Backup defaults, one card, four sections The PUT is a whole-object replace, so each card already had to resend the other three. One form, one request.
Tags, Hostname Aliases, Danger Zone Settings › own sections Configuration, not status.
Backup progress card Top of Overview, above the tiles Currently rendered inside the info card, below nine rows of static metadata.

If we build it

What this costs

The proposal is deliberately backend-free: every number on the Overview tab is derivable from data the view already fetches on mount.

No new endpoints

Last backup, 30-day success rate and the recent list all come from GET /agents/:hostname/reports, which the view already loads. Next run and the overdue badge come from /schedules and /stats/health, also already loaded. Repository count comes from /agents/:hostname/repos. “Run now” on a schedule row is the existing POST /schedules/:id/run.

Mostly existing components

BaseTabs, BaseModal, BaseSegmented, EntityStatusBadges, EntityTags, BackupProgressCard, EmptyState and AgentDangerZone all carry over. New: an AgentHeader, an AgentOverviewTab, an AgentBackupsTab and an AgentSettingsTab that hosts the existing panels.

Shrinks the view

AgentDetailView.vue is 1,320 lines carrying the tab shell, the backup list, two inline expanders, three dialogs and the WebSocket wiring. Splitting along the four tabs follows the same pattern F-24 applied to RepoDetailView, which came out at 367 lines.

Open questions

Does a fourth tab beat a settings link in the header? Should the imported-host variant drop the Backups tab entirely, since imported hosts have reports but no schedules? And the 30-day window is a guess — 7 days may read better for hourly schedules.
